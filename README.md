# ขอทำประกันภัยรถยนต์ · โตโยต้า กาญจนบุรี

แบบฟอร์มขอทำประกันภัยรถยนต์ 2 แบบในหน้าเดียว — **พนักงานทำประกันเอง** และ **พนักงานแนะนำลูกค้าทั่วไป**
หน้าเว็บเป็นไฟล์ static ล้วน (GitHub Pages) · ข้อมูลเก็บที่ Supabase

| ไฟล์ | ใช้ทำอะไร | ต้องเข้าสู่ระบบ |
|---|---|---|
| `index.html` | ฟอร์มยื่นคำขอ | **ไม่ต้อง** — ลูกค้าที่พนักงานแนะนำมาก็กรอกเองได้ |
| `staff.html` | รายการคำขอ · อัปเดตสถานะ · เปิดเอกสารแนบ | **ต้อง** (ในนี้มีที่อยู่/เบอร์โทรลูกค้า) |
| `config.js` | URL + anon key ของ Supabase | — |
| `style.css` | ธีมแบรนด์ ใช้ร่วมกัน 2 หน้า | — |
| `supabase/schema.sql` | ตาราง · RLS · RPC · Storage | — |
| `supabase/employees.sql` | รายชื่อพนักงานสำหรับค้นรหัส | — |

## ติดตั้ง 5 ขั้น

### 1. สร้างโปรเจกต์ Supabase
[supabase.com](https://supabase.com) → **New project** → จดรหัสผ่านฐานข้อมูลไว้
เลือก region **Southeast Asia (Singapore)** จะเร็วที่สุดสำหรับผู้ใช้ในไทย

### 2. สร้างตารางและกฎความปลอดภัย
Dashboard → **SQL Editor** → **New query** → วางไฟล์ `supabase/schema.sql` ทั้งไฟล์ → **Run**

ควรได้ `Success. No rows returned` · รันซ้ำได้ถ้าต้องแก้แล้วรันใหม่

### 3. นำรายชื่อพนักงานเข้า (สำหรับค้นชื่อจากรหัส)
วางไฟล์ `supabase/employees.sql` ใน SQL Editor → **Run**

> สร้างไฟล์นี้ใหม่เมื่อรายชื่อเปลี่ยน:
> ```
> node scripts/export-employees.cjs                     # ทุกคนที่ยังใช้งานอยู่
> node scripts/export-employees.cjs --dept ขาย ประกัน    # เฉพาะบางแผนก
> ```
> อ่านจาก `E:\VoucherSystem\data\voucher.db` แบบ read-only · **ส่งขึ้นคลาวด์แค่ รหัส/ชื่อ/แผนก**
> ไม่ส่งรหัสผ่าน ลายเซ็น หรือตำแหน่ง

### 4. ใส่คีย์ใน `config.js`
Dashboard → **Project Settings → API** แล้วคัดลอกมา 2 ค่า:

```js
window.SUPA = {
  url:     'https://xxxxxxxx.supabase.co',   // Project URL
  anonKey: 'eyJhbGciOi...',                   // anon / public
};
```

> 🔒 **anon key ปลอดภัยที่จะอยู่ในไฟล์นี้** — ออกแบบมาให้ฝังในหน้าเว็บ ตัวที่คุมสิทธิ์จริงคือ RLS + RPC
> ⚠️⚠️ **ห้ามใส่ `service_role` key เด็ดขาด** — ตัวนั้นข้าม RLS ได้ทุกอย่าง

### 5. เปิด GitHub Pages
Repo → **Settings → Pages** → Source: **Deploy from a branch** → Branch: `main` / `(root)` → **Save**

รอ 1–2 นาที แล้วเปิด `https://<ชื่อผู้ใช้>.github.io/<ชื่อ repo>/`

## สร้างบัญชีให้เจ้าหน้าที่

`staff.html` ใช้ Supabase Auth และ **ไม่มีปุ่มสมัครสมาชิก** โดยตั้งใจ — ผู้ดูแลสร้างบัญชีให้เท่านั้น
เจ้าหน้าที่ **เข้าด้วยรหัสพนักงาน + รหัสผ่าน** และเข้าได้ **เฉพาะเจ้าหน้าที่ประกัน**

ต้องมีครบ 2 อย่างถึงจะเห็นข้อมูล:

1. **รหัสอยู่ในตาราง `ins_staff`** — สร้างรายชื่อจากทำเนียบในออฟฟิศ (ตำแหน่ง/แผนกมีคำว่า "ประกัน")
   ```
   node scripts/export-ins-staff.cjs      → supabase/ins-staff.sql (ไม่อยู่ใน repo) → วางใน SQL Editor → Run
   ```
2. **บัญชี Auth** — Dashboard → **Authentication → Users → Add user**
   - Email: `<รหัสพนักงาน>@staff.toyotakan` เช่น `11001246@staff.toyotakan` (ไม่ต้องมีอีเมลนี้จริง)
   - ตั้งรหัสผ่าน · ติ๊ก **Auto Confirm User**

มีบัญชี Auth แต่รหัสไม่อยู่ใน `ins_staff` → ล็อกอินแล้วขึ้น "บัญชีนี้ไม่มีสิทธิ์" และ RLS ไม่ให้เห็นแม้แต่แถวเดียว
ปิดสิทธิ์คนที่ย้ายแผนก: `update public.ins_staff set active = false where emp_id = '...';`
ลืมรหัสผ่าน: ตั้งใหม่ในหน้า Users (ส่งอีเมลรีเซ็ตไม่ได้ เพราะไม่ใช่อีเมลจริง)

> แนะนำปิด **Authentication → Sign In / Providers → Allow new users to sign up** ด้วย

### แจกลูกค้าให้เจ้าหน้าที่อัตโนมัติ
- ใบใหม่ถูกแจกให้ **เจ้าหน้าที่ที่มีใบสะสมน้อยที่สุด** ทันทีที่ลูกค้าส่ง (เสมอกันสุ่ม · ไม่นับใบที่ยกเลิก) — `ins_pick_assignee()`
- เจ้าหน้าที่ (`ins_staff.role = 'agent'`) **เห็นเฉพาะใบของตัวเอง** (บังคับที่ RLS)
- บัญชีกลาง (`role = 'admin'` เช่น `insurance@toyotakan.co.th`) เห็นทุกใบ · มีแถบยอดสะสมต่อคน · เปลี่ยนผู้ดูแลได้ในหน้ารายละเอียด · ไม่ถูกนับเข้ากองแจกงาน
- ⚠️ นับสะสมตั้งแต่เริ่มใช้ → **เพิ่มเจ้าหน้าที่ใหม่ คนนั้นจะได้ใบใหม่ต่อกันจนยอดทันคนอื่น**
- ปิดคนที่ลา/ย้ายออกจากการแจก: `update public.ins_staff set active = false where emp_id = '...';` (ใบเดิมของเขาต้องให้บัญชีกลางย้ายให้คนอื่น)

## ความปลอดภัย — สิ่งที่ทำไว้แล้ว

| เรื่อง | วิธีจัดการ |
|---|---|
| anon key อยู่ในหน้าเว็บ ใครก็อ่านได้ | ทุกตารางเปิด RLS และ **ไม่มี policy ให้ anon เลย** — แตะตารางตรง ๆ ไม่ได้แม้แต่แถวเดียว |
| ทางเข้าของฟอร์มสาธารณะ | RPC 3 ตัวเท่านั้น (`ins_lookup_emp` · `ins_submit` · `ins_add_file`) แต่ละตัวทำได้แคบ ๆ |
| ดึงรายชื่อพนักงานทั้งองค์กร | `ins_lookup_emp` รับทีละรหัสและคืนแค่ชื่อ+แผนก — dump ทั้งตารางไม่ได้ |
| บอทยิงใบขยะ | กับดักช่องซ่อน (honeypot) + เพดาน **40 ใบ/10 นาที/IP** |
| คนแนบไฟล์ใส่ใบคนอื่น | ต้องมีกุญแจประจำใบ (`upload_token`) ที่คืนครั้งเดียวตอนยื่น และหมดอายุ 60 นาที |
| ไฟล์แนบรั่ว | bucket ไม่ public · anon **อัปโหลดได้ แต่อ่านไม่ได้** · เจ้าหน้าที่เปิดผ่าน signed URL อายุ 2 นาที |
| กุญแจแนบไฟล์หลุดไปกับรายการ | `staff.html` อ่านผ่าน view `ins_requests_view` ซึ่งไม่มีคอลัมน์นั้น |

### ⚠️ เรื่องที่ควรรู้
- **ข้อมูลลูกค้าอยู่บนเซิร์ฟเวอร์ Supabase** (คลาวด์ต่างประเทศ) ไม่ได้อยู่ในออฟฟิศแล้ว — ต่างจากระบบเดิมที่เข้าถึงได้แค่ใน LAN
- **ฟอร์มเปิดสาธารณะจริง ๆ** ใครก็เปิดลิงก์ได้ · honeypot + rate limit กันบอทหยาบ ๆ ได้ แต่ถ้าโดนยิงหนักควรเพิ่ม [Cloudflare Turnstile](https://developers.cloudflare.com/turnstile/)
- **ยังไม่มีการแจ้งเตือน** เมื่อมีใบใหม่ (ระบบเดิมมี LINE) — ต้องเข้ามาดูที่ `staff.html` เอง · ถ้าต้องการ ทำเป็น Supabase Database Webhook ยิงเข้า LINE Messaging API ได้
- ระบบเดิมในออฟฟิศ (`insurance-req.html` บนเครื่องเซิร์ฟเวอร์) **ยังใช้งานได้ตามปกติ ไม่ถูกแตะ** — ทั้งสองที่เก็บข้อมูลแยกกัน

## โครงข้อมูล

- **`ins_requests`** — 1 แถว = 1 ใบคำขอ · เลขที่รูปแบบ `INS-2609-001` (แยกชุดตามเดือน เวลาไทย)
- **`ins_files`** — metadata ของไฟล์แนบ (ไฟล์จริงอยู่ใน Storage bucket `ins-files`)
- **`employees`** — รหัส/ชื่อ/แผนก สำหรับค้นตอนกรอกฟอร์ม
- **`ins_seq`** — ตัวนับเลขรันต่อเดือน
- **`ins_submit_log`** — บันทึกการยื่นไว้ทำเพดานกันยิงรัว

สถานะการติดตาม: `new` รอตรวจสอบ → `contacted` ติดต่อแล้ว → `quoted` เสนอราคาแล้ว → `done` ปิดการขาย · หรือ `cancelled` ยกเลิก
